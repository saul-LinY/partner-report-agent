# 项目简介

每位成员负责的每个项目有一份面向非技术读者的简介：一句话、简介、能做什么、现状、待解决。成员总览和成员页展示它，工作卡生成也把它当作项目说明使用。内容只来自已上传的会话，不读取、不上传任何项目文档。

## 怎么生成

Worker 在每轮循环里处理一个会话（`apps/worker/src/project-profile.ts`）：

1. 取该成员某个项目里「预处理后保留」的会话，同一项目只处理最早的未读会话，所以项目笔记总是按时间顺序推进。会话新增或再次更新后会重新读取。
2. 把会话分成不超过 14000 字符的片段，每片一次模型调用，输入是当前笔记加这一片对话；模型返回完整的新笔记。长会话分多片，轮次编号 `S{会话序号}T{轮次}` 在整个项目内稳定。
3. 校验后写入 `project_profiles.note`，并记录 `project_profile_sessions`（已读会话、序号、状态）。
4. 简介同步写入 `projects.description`（来源标记 `profile-note`）。人工确认过的项目说明不会被覆盖；工作卡生成原本就读取该字段。

使用团队设置里的 `central_model`，需要 `MODEL_API_KEY` 和能访问该模型的 `MODEL_API_BASE_URL`，没有配置时 Worker 跳过这一步。

失败处理：单个会话失败后按 30 秒起指数退避重试，连续 3 次失败记为 `failed` 并写入 `last_error`，不会卡住同项目后面的会话。

## 写作和隐私规则

规则在 `packages/contracts/src/privacy.ts` 和 `project-profile.ts`，代码检查，不只靠提示词：

- 送给模型前，去掉系统注入的块（附件说明、`<…-context>` 等），隐藏密钥、口令、地址、本地路径、邮箱、手机号。「口令设成 123456」这类写在句子里的凭证，会隐藏关键词后 40 字内所有 6 位以上的字母数字。
- 每个字段有字数上限：一句话 30、简介 120、功能每条 25（最多 5 条）、现状 120、待解决每条 60（最多 3 条）。
- 禁用技术词、英文名称（仅 AI、App、Web、PDF、MVP 除外）、涉及密钥口令的词；一句话、简介、现状、待解决里不写界面样式。
- 违规的字段先让模型重写一次，仍违规就删除该字段，宁缺毋滥。
- 每个字段必须带引用；引用不存在，或指向谈论凭证的轮次，该字段被删除。
- 读取接口每次都会重新套用这些规则，规则收紧后已存的笔记也会被过滤。

## 接口

- `GET /v1/admin/project-profiles`：该团队全部简介。领导页不展示引用依据；引用只在生成时用来校验每个字段确有出处。

## 运维

- 每个会话约 33 秒（2026-11-03 在 `deepseek-v4-pro:cloud` 上实测，含违规重写）。每周约 25 个会话时，一个周期需要十几分钟；最忙的一周约 44 个。首次补跑全部历史会话需要一个多小时。进度可从 `project_profile_sessions` 看到，中断后会从未读的会话继续。
- 要整体重建某个项目的简介：删除对应的 `project_profiles` 行，会话记录随之级联删除，Worker 会重新从头读取。
- 模型上游不可用时（例如网关对某个模型返回 502 或 404），会话停留在待处理并退避重试；先在团队设置里换一个网关上可用的模型。
