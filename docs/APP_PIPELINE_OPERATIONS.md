# App 完整处理流水线

更新日期：2026-11-03。

## 正常流程

1. App 读取本人获准项目的会话，按当前开放周期打包，经清单、分包校验和整包回执确认上传。
2. API 在确认完整接收的事务内登记会话分析任务。Worker 也会补登记升级前已收到的完整包。
3. Worker 分段读取完整来源，为每条贡献校验消息引用和日期，区分成果、进展、决定、阻塞和下一步。只有用户提问不能作为已完成成果。无有效内容的会话记录为忽略。
4. 同一成员本期来源处理完成后，按项目归并成果材料、生成工作卡片及覆盖快照，发送 App 待审核通知。
5. 本人在 App 确认、忽略或提出修改意见。重新生成保留固定成果材料和用户确认的项目状态。全部卡片处理完成后生成不可变审核快照。
6. 到周截止时间，系统等待分析及卡片任务完成，冻结本期来源；所有成员审核完成后生成并归档团队周报。管理员也可以在审核完成后提前汇总。提前生成会完成该周期。

系统不会为了完成流程自动确认当前真实卡片。现有团队的审核超时规则继续适用。

## 启动和模型

常规部署同时运行 API、Web、Worker，先执行 `npm run db:migrate`。开发可使用 `npm run dev`。

本机 App 联调环境：

```sh
npm run app:services -- start
npm run app:services -- status
npm run app:services -- restart api
npm run app:services -- restart worker
npm run app:services -- stop
```

本机脚本使用 `partner-report-collector-test` 容器、API 4314、Web 4313，在 `.local/collector-*.log` 保存服务日志，在私有配置文件保留 Session 签名密钥。原有 `.local/collector-dev.mjs` 启动脚本只供历史记录参考，请使用上述命令。

可以通过 `COLLECTOR_DATABASE_URL` 覆盖本机数据库。脚本默认连接本机 Ollama；其他模型网关通过 `MODEL_API_BASE_URL`、`MODEL_API_KEY` 指定。远程网关不会自动使用本机占位凭据。团队模型必须在管理设置中与网关实际可用模型一致；本机当前可选 `qwen3.6:27b-mlx`。云模型需要网关侧真实授权。

网关须提供 `/v1/responses`。不支持 developer 消息角色的网关设置 `MODEL_INSTRUCTION_ROLE=system`；本机脚本对本机网关使用该配置。结构化输出仍经本地 Schema 和证据校验，不接受不匹配结果。

## 监控和恢复

管理端“监控与排障”分为三页：

- **用户日志**（`/admin/user-logs`）：左侧按成员列出设备、App 版本、在线状态（最近日志到达不超过 5 分钟）、最近上传、窗口内错误数和严重度；右侧只显示所选成员的设备状态（启动阶段、项目与已允许项目、会话、无法读取、待上传、扫描与上传进度、定时上传计划、通知权限）、上传批次及处理阶段（整包接收、会话分析、卡片任务、审核、周报）、按时间排列的 App 事件（可按级别、阶段、团队时区日期或最近 24 小时筛选，可展开细节）。不同成员的日志不混排。
- **系统日志**（`/admin/system-logs`）：中台组件健康、API／数据库探测、Worker 心跳与能力、事件摘要，以及任务、通知、Outbox 和周报执行的明细（任务类型、成员、尝试次数、错误码及脱敏错误信息、耗时、租约和重试时间、幂等键、关联上传和周期），可请求模型分析。
- **异常巡检**（`/admin/inspection`）：见下节。

Worker 独立每 15 秒上报心跳，超过 90 秒未到达标记离线。App 独立每 30 秒上报状态，并轮询处理进度；退出 App 后不再上报。

## 异常巡检

Worker 每 5 分钟对每个团队巡检一次，管理员也可在页面点击“立即巡检”（`POST /v1/admin/inspection/run`，同一团队同一时间只运行一次，进行中返回 409）。发现保存在 `inspection_findings`，运行记录保存在 `inspection_runs`。同一规则和对象只保留一条发现；再次检出更新最近发现时间和次数，下一次巡检不再检出则自动标记已解决。

| 链路 | 规则 |
| ---- | ---- |
| App（按设备） | 心跳（超过 5 分钟警告，超过 30 分钟严重）；绑定与权限同步（权限同步失败、认证 401）；扫描（最近扫描错误、无法读取会话）；上传（最近上传错误码、整包接收超过 15 分钟未推进、已开启自动上传但超过计划时间 30 分钟仍无完成上传）；通知（权限被拒绝或未配置、通知超过 15 分钟未送达） |
| 系统 | API／数据库探测；Worker 心跳（超过 90 秒）；任务队列（租约过期、等待超过 1 小时、等待重试）；会话分析失败；卡片生成失败；周报（生成中超过 1 小时、任务失败）；通知投递；模型网关（近期同类模型错误码） |
| 跨链路 | 完整包已收但超过 10 分钟未登记分析；分析全部完成但超过 10 分钟未登记卡片任务；设备已上传本期但成员没有审核记录 |

新出现或严重度升级的发现自动排队 `ANALYZE_INSPECTION_FINDING` 任务，由 Worker 通过模型网关生成研判（摘要、可能原因、影响、建议动作、可信度、相关链路），输入只包含脱敏证据和该成员或任务的近期事件。页面如实显示排队、分析中、完成、失败及错误；未配置模型时直接说明。可点击“重新研判”。由任务引起的发现在详情中直接提供重试和清除（`POST /v1/admin/agent-jobs/:id/retry`、`/clear`），不再有单独的异常任务页面。

| 状态                    | 后续动作                                     |
| ----------------------- | -------------------------------------------- |
| 分包接收中              | App 保留待传包并重试，只有整包回执才记为成功 |
| 等待分析 / 分析中       | Worker 自动处理                              |
| 分析等待重试            | 按下次重试时间自动续跑，也可管理员重试       |
| 分析失败 / 卡片生成失败 | 检查模型配置、错误码，再点击重试处理         |
| 无可汇报贡献            | 来源处理完成，没有足够工作事实               |
| 待审核                  | 本人在 App 或 Web 处理卡片                   |
| 审核完成，待汇总        | 等待截止时间，或管理员提前汇总               |
| 周报生成中              | 在异常巡检或系统日志查看任务进度和错误    |
| 周报已归档              | 已生成最终版本及通知                         |
| 模拟历史                | 仅保留查看，不进入真实来源处理               |

完整包通过 `collector_upload_jobs` 关联分析任务。相同成员、周期、会话与内容版本复用任务；新内容替代待处理的旧版本。长会话逐段检查点写入 `agent_jobs.output_payload`，失败后保留已完成分段。只有最后来源校验成功才替换有效贡献。

新证据会更新原项目卡片并重新要求审核，保留其他项目及卡片身份；写入卡片前复核来源及审核版本，过时生成结果不覆盖新决定。若重分析删除最后有效事实，原卡片也需重新确认。周报只读取已确认快照，提交前再次核对快照和待处理任务。

周报生成中遇到新证据或审核变更时，旧结果作废，退回等待审核；重新审核完成后自动重新排队。已归档周期的后到分析不覆盖归档事实。会话时间按团队时区及截止的具体时分归属，起点包含、终点不包含。

`client_state` 仅保存白名单计数、状态和计划，不包含目录、会话正文或密钥；日志事件也采用严格白名单。原始会话仅存在完整包存储中。测试设备用 `collector_devices.status='test'` 隔离；带 `synthetic=true` 的历史样例不作为真实周报比较依据。

## 验证

`apps/api/src/collector-pipeline.integration.test.ts` 在独立租户中验证上传、分析失败、管理员重试、检查点续跑、去重、项目卡片、通知、新来源重新审核、原生审核命令、快照、周报生成和归档。模型输出在测试中受控；实际模型联调须另查真实任务和产物。

```sh
RUN_DB_TESTS=1 DATABASE_URL=postgres://... npm test
npm run typecheck
npm run build -w @partner-report/web
```

数据库测试应使用独立测试数据库，避免运行中的 Worker 领取测试任务。原生测试使用 Xcode 的 WeeklyReport scheme；打包与安装方法见 `apps/macos/README.md`。
