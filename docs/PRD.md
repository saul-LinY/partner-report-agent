# Partner Report 当前产品定义

## 目标

在不上传完整 Codex 对话的前提下，采集用户允许项目中的有效 Session，按周生成可确认、可修改、可追溯的项目工作卡片，并为团队汇总提供结构化素材。

## 用户端

用户不安装额外桌面应用，日常操作都在已有工具中完成：

- Codex：安装并绑定插件，按计划采集获准项目，凭据缺失或失效时自动恢复原连接。
- 飞书：确认审核身份，允许或拒绝项目采集，并通过自然语言修改、通过或忽略每周工作卡片。
- Web 管理端：管理员维护 Partner、周期和团队报告，并查看安全的采集诊断信息。

产品不提供个人周报，也不在飞书中提供复杂编辑器；工作卡片支持用自然语言提出修改意见并重新生成。

飞书工作卡片默认展示完整总览和全部每日进展，不按字数截断正文。接近消息容量上限时，按段落和日期分页；单段超长时按句子或完整 Unicode 字符继续拆分，保留全部内容。用户通过同一张卡片的“上一页 / 下一页”查看内容，无需登录中台。每页保留整张项目卡片的修改、通过和忽略操作；翻页只改变展示，重新生成后从新版第一页开始，旧版本翻页操作不能继续展示旧内容。

## 数据与版本

- 首次插件绑定幂等创建官方每日定时任务，用户不管理任务配置。
- 未允许项目只登记匿名项目键、显示名和 Session 数，不读取 Session 内容。
- 首张项目权限卡按 Partner 工作邮箱私发，回调中的 `open_id` 用于建立后续私聊投递身份。
- 工作卡片按周期生成并逐项审核；每次决策使用版本号控制并发，旧卡片不能覆盖新状态。
- 审核完成后冻结不可变快照，作为团队报告的结构化输入。

## 团队周报

- 本周事实来源是已确认的完整工作卡片，包括项目用途、总览、每日进展及当前状态；项目用途不代表本周新增成果。
- 先按负责人和项目匹配紧邻上一周期的最终周报。优先使用稳定标识，历史表格按同名负责人和项目精确匹配；缺失或存在歧义时不作推断。
- 第一阶段逐项目调用团队选定的模型，结合完整卡片和匹配的上周记录，描述本周成果、较上周变化和当前阶段。提示词强约束约 200 字，目标 180 至 220 字；不通过代码校验字数、截断正文或因字数重试。
- 第二阶段使用同一模型，结合完整工作卡片和各项目表述，生成自然 STAR 结构的团队总览，以及仍实际影响关键目标或交付的项目阻塞。没有第三阶段的模型检查。
- 周报正文使用“项目负责人 / 项目名称 / 较上周进展”三列表格。阻塞按负责人和项目分层列点，无明确阻塞时省略整个部分。普通迭代、尚未上线或效果待验证不自动视为阻塞。
- 全篇使用通俗语言，突出功能、成果和目的，不罗列接口、代码或工具调用。来源不足时保留不确定性，不编造上周状态、商业效果或项目阻塞。
- 新版本保存结构化项目进展，供下一周准确比较；历史周报仍可查看。管理员手工编辑正文后，以修改后的正文作为后续比较依据。

## 系统职责

- Plugin：发现项目、遵守项目权限、提取单个有效 Session、幂等上传、上报采集健康状态。
- API/Worker：保存权限、按周聚合工作卡片、冻结确认结果、生成团队报告，并通过 Outbox 驱动飞书投递。
- 飞书应用：处理身份确认、项目权限，以及工作卡片重新生成、通过或忽略。
- Web 管理端：管理组织数据、周期、团队报告和采集诊断。

## 验收重点

1. 未授权项目不会读取或上传 Session 内容，权限决定可逐项或批量提交。
2. 首次项目权限回调建立飞书身份，后续卡片只私发到已绑定的 `open_id`。
3. 工作卡片可反复提交自然语言修改意见；只有用户通过或忽略当前卡片后才展示下一项，全部处理后冻结审核快照。
4. 旧版本卡片和重复回调不能覆盖最新状态，发送和回调均可幂等重试。
5. 初次绑定后的定时采集任务不会重复创建，连接失效可在飞书确认恢复。
6. 运行代码、数据库当前结构和文档均不依赖 macOS App、Widget 或个人周报入口。
