# CC Switch 采集链路复查与补齐

日期：2026-10-29。基准：CC Switch 4.0.21，提交 `6d6b7162f122ac0ce1356a14688c8c4f712db3c8`。原始源码通过相邻仓库的 Git 对象只读核对；App 不需要安装 CC Switch，也不依赖该仓库运行。

## 复查结论

此前完整保留的是多数正文解析代码；目录定位、旧格式发现、来源上下文和标题读取没有全部接通。Hermes 的 `finish_reason` 也是保留解析代码未投影到正式回复判断的实例。不能把“解析器文件保留／编译通过”当成完整采集链路。

当前产品代码位于 `apps/macos`，保留用户指定的 8 种 Agent。新的目录发现层与元数据定位入口连接到同一个随 App 打包的 Reader，标题和正文复用实际来源身份。上游完整扫描器会提取首条提问／摘要，因此没有直接复用到未批准项目的发现阶段；只投影定位字段的适配保留了项目确认边界。

## 默认使用过程

1. 安装后的第一次打开自动扫描；当前为本机开发 App，没有另行实现安装器阶段的用户目录扫描。
2. 检查默认目录、当前进程可用的路径环境变量、Agent 本机路径配置、CC Switch 设备路径覆盖与已确认的多账号／profile 布局；默认来源与额外来源并存。
3. 将实际找到的 Agent 目录、会话路径、配置来源、扫描时间和诊断写入当前用户 `WeeklyReportLocal/source-discovery.json`，权限 0600。仅保存路径相关白名单环境字段，不保存密钥、供应商配置或会话正文。
4. 已发现路径在下次启动复查，避免从终端打开时可见的路径在之后从 Finder 打开时消失。后续仍按每轮扫描完成后约 60 秒、切回窗口、唤醒和手动刷新复查。
5. 新项目默认待确认。获准后才读取标题和正文；Rust 再核对来源身份、项目及父子关系。设置页展示实际路径，多处来源可通过提示查看；不能把预设目录当成实际发现结果。

## 补齐范围

| 环节 | 原先的断点 | 本轮处理 |
| --- | --- | --- |
| Codex | 单版本 state DB 是扫描前提；外置索引与无索引历史遗漏 | 合并全部版本 DB；解析根 `sqlite_home`／`CODEX_SQLITE_HOME`；枚举 sessions 与 archive；普通／压缩无索引文件通过批量元数据命令定位 |
| Claude Code | 仅默认及单目录；多账号遗漏；标题阶段未预检迁移范围 | 补 `CLAUDE_CONFIG_DIR`、CC Switch 设置及合法多账号目录；标题解码前检查 cwd／relocatedCwd；区分 CLI 会话身份与 SDK 请求身份 |
| OpenCode | 缺 XDG、指定 DB、V2 与旧 JSON 的发现 | `XDG_DATA_HOME`／`OPENCODE_DB`、V1／V2 元数据查询；旧 session JSON → message → part 的定位、授权读取和内容变化指纹 |
| Pi | native sessionDir 和环境目录没有进入发现 | 对齐 Agent 根、绝对 session override、JSON5 settings；相对 sessionDir 明确需要启动项目上下文，不猜 cwd |
| Oh My Pi | 自定义根／profile／XDG 组合遗漏；多目录批次被第一目录限制 | 枚举配置根与 XDG 命名 profile；保留默认历史；每个来源目录独立读取，避免与 Pi 共用环境变量导致错误归类 |
| Hermes | Home 覆盖、文件会话、schema 替代列、正式停止字段未接通 | `HERMES_HOME`／CC Switch 目录、SQLite＋带头部 JSONL；兼容元数据列差异；保留原生 finish_reason、模型及时间 |
| Grok Build | 自定义 sessions 的 archive 未补扫 | 从同一个 Grok 根派生 sessions 和 archived_sessions，继续核对 summary 与 events 结束信号 |
| Antigravity | 仅默认 CC Switch 数据根；无文本导出静默丢失；旧 schema 缺结束列报错 | 导入已知 Tauri app_paths 数据根；CLI／桌面／私有 profile；仅索引会话明确提示文本不可读；缺结束证据只保留未完成提问 |
| 来源身份 | 全局按 provider＋nativeID 合并 | 来源键包含实际存储根及项目；Codex 同根 archive／continuation 仍聚合，跨 profile 和跨项目隔离 |
| 标题 | 重新猜默认 home，可能与正文来源不一致 | 按源文件真实上下文、外置索引和实际数据库查询；V2 标题优先；未知标题不编造 |

## 验证和边界

可复现的 Swift 测试覆盖首次启动扫描、跨用户 home、环境变量、CC Switch 覆盖、多账号／profile、外置数据库、无索引历史、实际目录持久化，以及完整的“发现 → 本地确认 → 打包 Reader → 提问与正式回复”流程。Rust 测试覆盖元数据输出不含正文、压缩输入、旧格式授权、错误项目、父子关系、完成信号与数据结构差异。真实验证仅使用 App 已允许的项目，不变更其他项目权限、不联网。

目录中的任何任意自定义位置并不能无条件自动找到：仅存在于另一个终端启动命令、没有保存到已知配置的路径，以及相对 sessionDir，都需要用户补充实际目录。GUI 不会通过运行用户 shell 来加载环境，也不会遍历整台电脑找聊天正文。

CLI／桌面共用已验证本地存储时复用同一路径；远端／云会话、独立未识别的桌面存储、Antigravity 未导出的二进制正文不冒称支持。临时目录、子 Agent、未登记的非 Git 目录仍按既有策略处理。

元数据定位可能经过含正文的 JSONL 缓冲区或邻接 SQLite 数据页；承诺未确认前不提取、缓存或展示正文，不宣称实现字节级物理隔离。元数据行上限为 8 MiB，超限显示定位提示，不静默记为读取成功。

## 最终验收结果

47 项 XCTest 与 36 项 Rust 测试通过。新增 App 集成测试实际调用随 App 打包的 CLI，覆盖首次扫描与重启、环境变量消失后的目录记忆、Codex 无索引、双 OMP profile、Hermes JSONL、OpenCode 旧存储，以及先确认项目再读正文。

真实回归还发现并修复了 Codex 压缩历史里的字符串 message 字段、Claude SDK/backend session_id 与 CLI sessionId 的区别，以及正在写入的未换行尾行。完整坏行仍拒绝，已知目录字段类型错误仍拒绝，跨项目限制没有放宽。
