# 每日项目进展

运行总览默认打开「项目进展」，使用周一到周日排列的月历。首页保留成员筛选、项目列表和月份切换；日期格只展示项目名称，点击后阅读当天各项目的完整记录。人员管理与生成设置保留在原有页签。

选中项目后展示当前阶段条及最近成果。阶段为需求梳理、开发实现、联调测试、交付验收、完成；前四项通过「设置阶段 / 调整阶段」确认，允许业务变化时回退。完成仍由明确的项目完结事件确认，重新开启会清空此前阶段。没有明确阶段时展示最近成果，不用周卡的任务完成状态推断整个项目完成。

阶段保存在已有里程碑事件的可选 `stage` 字段中，不新增表；修改沿用权限、版本冲突及历史留存机制。时间统计、冲突提醒与核查记录收进「项目详情」，不在首页堆叠。

## 数据更新与每周核查

- 页面每 60 秒刷新，也支持手动刷新；展示用户审核通过的周工作卡片中 `payload.dailyProgress` 的原文，按成员、项目和条目日期对应到日历。
- 待审核、已忽略的周卡和原始采集摘要不进入日历，也不影响最近成果与贡献记录天数；审核通过后自动展示，撤回或忽略后在下次刷新时移除。日期详情可打开对应周卡核对。
- 未知、无效或未来的日期标为日期待核查，不使用采集时间或卡片创建时间补造日期。没有每日进展的周卡不以整周摘要代替。
- 现有网页周卡增加「项目时间核查」入口，可在已审核的历史周卡补录时间。每天的成果仍沿用已有周卡生成、修改、审核流程；本功能不创建另一份周报，也不增加飞书交互动作。

## 时间含义

时间属于「成员 + 项目」的参与记录，不改变共享项目本身的状态。两个成员在同一项目可以有不同的开始和完结时间，同一个成员的多个项目可以重叠。

事件顺序为开始 → 暂停 → 恢复 → 完成；暂停、恢复可重复，完成后可重新开启。开始必须明确确认，可以单独添加“接口联调完成”等里程碑，其日期和说明不改变推进状态或工期。第一条贡献不是默认开始日，周卡里的任务完成也不代表项目完结。

| 指标         | 计算方式                                                       |
| ------------ | -------------------------------------------------------------- |
| 项目跨度     | 第一次确认开始至最后完成；未完成时至今天，包含首尾，使用自然日 |
| 暂停天数     | 暂停当天起，恢复当天之前；尚未恢复则算到今天                   |
| 推进区间天数 | 确认处于推进状态的日期；不等同于实际投入工时                   |
| 贡献记录天数 | 有贡献的历史日期去重；成员层级再跨项目去重                     |

按天记录，同一天仅支持开始（或重新开启）并完成，记为 1 天；其他同日切换需要核查，小时级中断不据此折算工时。完成后重新开启的中间空档计入总跨度，但不计入推进和暂停。贡献出现在已确认推进区间之外时保留原始贡献并显示冲突提示，不自动改写时间事件。

月份切换只影响日历记录，项目最新成果和详情指标始终覆盖历史并截至今天。查询窗口最长 93 天，通过翻页查看更早记录。页面不相加并行项目时长，不推断投入比例。

## 存储与接口

迁移 `0037_project_participation_timeline.sql` 新增 `project_participations` 和 `project_participation_versions`，不回填或推断历史状态。

- `GET /v1/admin/project-progress?from=YYYY-MM-DD&to=YYYY-MM-DD`：默认当前月第一天至今天的管理员团队视图；单个数据库快照读取已审核周卡和时间，避免刷新时重复计算。
- `GET /v1/project-progress/participations/:partnerId/:projectId`：读取当前版本和最近 20 次核查历史；所有版本在数据库保留。
- `POST` 同一路径：提交 `baseVersion`、完整 `events`、必填核查 `note`，可选当前周卡 `reviewId`。

管理员只能修改当前团队成员及项目，成员只能修改自己的参与记录。周卡关联必须匹配成员、项目、团队和租户。更新在事务内锁定成员及参与记录，版本冲突返回 409，不覆盖草稿；当前记录、历史版本、操作者和审计日志原子写入。

本版为小规模团队直接聚合已审核周卡，未做物化日汇总。数据量增长后可用相同去重规则维护日表；每日进展原文与审批来源仍须保留。

## 发布与验证

先在目标数据库执行 `npm run db:migrate`，再发布 API 和 Web。迁移为新增表；旧程序可以继续运行。仓库不包含真实贡献数据，真实数据预览单独保存在工作区产物目录。

验证：`npm run typecheck`、`npm run build`；设置独立的 `DATABASE_URL` 后执行 `npm test`（部分现有回归用例也依赖数据库）。专项数据库集成测试再设置 `RUN_DB_TESTS=1`，运行 `apps/api/src/routes/project-progress.integration.test.ts`；浏览器测试运行 `project-progress.spec.ts` 和 `admin-pages.spec.ts`。
