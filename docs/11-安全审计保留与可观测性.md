# 11 安全、审计、保留与可观测性

> 对应 PRD：FR-13、17 至 19、NFR-01 至 NFR-05、AC-11、AC-12、22、23。
>
> 前置依赖：02 至 10。基础能力从 02 开始随功能建设，本板块负责统一收口。

## 1. 目标

把多租户隔离、最小权限、数据最小化、删除/保留、审计、可靠性和运行可观测性提升为生产试点门禁，而不是依赖代码评审中的隐含约定。

## 2. 数据分类

| 级别 | 示例 | 存储/访问要求 |
| --- | --- | --- |
| S0 公共配置 | Schema 版本、通用模板 | 常规完整性保护 |
| S1 业务元数据 | Team、Project、周期、状态计数 | 租户隔离、授权访问 |
| S2 个人工作数据 | Fact、Work Item、个人 Report | Partner 所有权、严格审计 |
| S3 敏感证据/凭证 | Evidence、OAuth Token、删除请求细节 | 加密、单独权限、最短保留 |
| Local-only | 完整 transcript、未截断工具输出 | 默认不得离开 Partner 设备 |

每张表、对象存储前缀、日志字段和队列 Payload 需标注分类。S3 和 Local-only 禁止出现在普通日志、指标 Label、错误消息和飞书卡片。

## 3. 权限与租户隔离

### 3.1 服务端

- 认证层解析主体；授权层判断 action/resource，仓储层强制 tenant scope。
- 所有业务查询带 `tenant_id`，使用代码规则、集成测试和数据库策略（适用时）多层防护。
- Worker 消息包含 tenant，但从目标实体重新校验，防止伪造消息跨租户。
- 对象存储 key、缓存 key 和队列 topic/partition 含租户隔离信息。
- 任何 Support/Admin 紧急访问采用显式 break-glass、时限和审计。

### 3.2 角色边界

- Partner 只能访问自己的 Fact、Work Item、Review 和 Report。
- Team Admin 可看同步状态和审计元数据，默认不能看 Evidence 正文。
- Monitor 没有服务端读取权限，只接收最终团队报告。
- Plugin Token 只能上传所属 Partner 数据和领取所属实例 Job。

### 3.3 自动化测试

对每个读取/写入 API 生成 Partner A/B、Tenant A/B 的越权矩阵。跨租户拒绝必须记录安全审计，但响应不泄露资源是否存在。

## 4. 凭证与通信

- OAuth/Refresh Token 和服务凭证使用受控密钥加密，定期轮换。
- Plugin 使用短期 Token；撤销和实例禁用即时生效。
- 服务间请求使用短期身份、签名和防重放机制。
- 全链路 TLS；Webhook 验签并限制时间窗口。
- 密钥不得进入 Prompt、追踪 Span、错误聚合、测试 Fixture 或飞书消息。
- 日志和 Dump 在写入前做字段级脱敏。

## 5. 数据最小化

- Ingestion Schema 不提供完整 transcript 字段。
- Evidence 独立开关、长度限制、敏感扫描和内容类型白名单。
- 大段代码、环境变量、工具输出和附件内容默认排除。
- 被排除 Session 不保留可推断内容的标题/摘要。
- AI Provider 请求只发送当前阶段最小输入；团队生成不接触个人 Evidence。
- 对象存储 Artifact 设置私有访问和短期下载链接。

## 6. 保留与删除

### 6.1 策略参数

业务方必须在试点前确认：

- Fact、Evidence、个人/团队 Report、Artifact、AuditEvent 的保留时长。
- 撤销授权和离职后的历史报告处理。
- 法务保留例外及审批人。

实现不写死期限。`RetentionPolicy` 版本随数据对象记录，策略变更通过后台任务执行。

### 6.2 删除编排

```text
REQUESTED -> VALIDATED -> IN_PROGRESS -> VERIFIED -> COMPLETED
                               |-> PARTIAL_FAILED -> IN_PROGRESS
```

删除范围遍历 Fact、Evidence、当前投影、缓存、对象、搜索索引和待处理任务；不可删审计采用去标识化或策略允许的最小记录。删除后重建受影响 Work Item/Report 投影，已提交历史报告按已确认政策处理。

### 6.3 撤销流程 SLA

Token 立即失效；未提交同步事实按策略异步删除。任务必须有进度、失败重试、完成证明和审计，不能只返回“请求已收到”。

## 7. 审计事件

统一字段：

```text
event_id, occurred_at, tenant_id
actor_type/id, action, target_type/id
request_id, source_ip/device (最小化后)
before_ref, after_ref, result, reason_code
sensitivity, retention_class
```

必须覆盖：绑定/撤销、同步批次/Coverage、提取器/Prompt 版本、Partner 变更、Evidence 访问、Snapshot、报告生成/提交/锁定、团队聚合、Artifact、飞书交付、管理配置、删除和 break-glass。

审计日志追加写、防篡改、访问受限；不直接保存秘密或完整 Evidence。

## 8. 可观测性

### 8.1 指标

- Plugin 在线、版本和最后同步分布。
- Runner 状态、最后心跳/Hook/扫描/提取时间、下一静默截止及 DIRTY/QUIET_WAIT/EXTRACTING/待同步数量。
- Session 发现/读取/提取/上传成功率及 Coverage 差距。
- Re-analysis 排队和处理时间。
- 聚合/生成/渲染耗时、失败和成本。
- 飞书回调 ACK、处理、卡片更新和交付成功率。
- Partner 审核耗时、修改率和按时提交率。
- 队列积压、重试、死信和数据库/对象存储健康。

指标 Label 禁止使用 partner_id、session_id 等高基数/个人标识；用日志/Trace 做受控关联。

### 8.2 SLI/SLO 初始值

从 PRD 目标建立：卡片接收反馈 < 2 秒、普通重新聚合 < 60 秒、50 Session 增量同步 < 10 分钟。试点测量 p50/p95/p99 后冻结正式 SLO。

### 8.3 告警

至少包括：Runner 心跳中断、有 Hook 但超过静默截止仍未提取、批量上传连续失败、Coverage 突降、回调验签异常、队列积压、Report 生成失败、PDF 渲染失败、交付失败、跨租户拒绝异常升高、删除任务超时和 Plugin 版本不兼容。

## 9. 可靠性和故障补偿

- 所有外部写操作有幂等键和对账任务。
- 队列至少一次投递，消费者可重复执行。
- 定时任务支持人工补跑和指定周期重建。
- 单个 Session/Partner 失败不丢弃整个周期。
- Dead-letter 条目有分类、Runbook、重放和永久失败处置。
- 备份覆盖数据库、配置和 Artifact 元数据；恢复演练验证 RPO/RTO。
- Plugin 离线、飞书不可用、模型不可用和对象存储不可用均有真实降级状态。

## 10. 安全验证

- 威胁建模：本地 Plugin、设备码/OAuth、Webhook、Ingestion、Evidence、AI Provider、对象存储、Admin 和 Monitor 交付。
- SAST、依赖/许可证、容器、IaC 和秘密扫描。
- API 模糊测试、批量大小/压缩炸弹、Prompt injection、Webhook 重放。
- 跨租户、水平越权、角色提升、撤销 Token、过期下载链接。
- 敏感数据扫描验证日志、Trace、队列、错误、Prompt 和飞书内容。
- 删除完整性和备份中的保留策略验证。

## 11. Runbook

至少编写：

- Plugin 大面积离线/过旧。
- Runner 未启动、心跳中断、静默任务卡住和电脑休眠后积压。
- Session 同步积压或 Coverage 突降。
- Re-analysis Job 卡死。
- 飞书回调/消息故障。
- 报告生成或 PDF 渲染失败。
- 重复/不确定交付对账。
- 跨租户告警和凭证泄露响应。
- Partner 撤销/删除请求失败。
- 周期补跑与报告新版本交付。

## 12. 验收与退出标准

- AC-11 的 Partner、Monitor 和跨租户权限矩阵全部通过。
- 撤销后 Token 立即失效，AC-12 删除流程可验证完成。
- S3/Local-only 数据未出现在禁止的系统表面。
- 审计从 Fact 到报告和交付形成完整链路。
- 关键 SLI 有 Dashboard，告警和 Runbook 经故障注入验证。
- 重试/补跑/对账不会制造重复事实、修改或交付。
- 保留与离职策略由业务方签字确认，试点环境完成恢复演练。
