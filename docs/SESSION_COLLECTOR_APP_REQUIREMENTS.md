# 采集 App 的界面需求

更新时间：2026-11-04。本文记录需求讨论结果，不表示应用已实现。

## 应用形态

macOS 桌面应用，提供完整窗口；菜单栏作为常驻入口与后台状态入口。登录后自动启动默认开启。用户关闭窗口后仍可在后台采集、上传；明确退出应用与关闭窗口应区分。

应用名为 `weekly report`，页面效果图使用 4:3。按钮及选中态采用亮黄色，成功状态为亮绿色，失败为亮红色，等待为亮黄色；减少卡片装饰，以紧凑桌面工具为方向。App 图标是黄色底的深蓝色日历／周报图形，不使用文字图标。

## 三个主要页面

### 首页：项目会话

- 参照 CC Switch 的会话浏览方式，汇总各 AI 工具中已批准项目的全部可采集会话。
- Agent 选择弹窗按内容自然高度显示，底部不保留固定高度空白。
- 支持“全部应用”和按工具筛选，覆盖 Codex、Claude Code、OpenCode、Pi、Oh My Pi、Hermes、Grok Build、Antigravity。根据最新要求移除 OpenClaw、MiniMax Code、Gemini CLI、Kimi Code，仅保留 8 种来源；这里定义界面来源范围，不表示所有解析器已经实现或验证。
- 以项目筛选、会话列表和会话详情组织内容。列表展示标题、来源工具、项目、更新时间和上传状态。
- 会话名优先使用 Agent 保存的真实标题或用户重命名，不能用首条提问覆盖已存在标题；仅在没有原生标题时回退。标题仍只对已允许的项目读取。
- 侧边栏仅列出已批准的具体项目，不提供“全部项目”入口；默认选中第一个项目。会话列表、应用筛选计数和搜索均限定在当前项目内。
- 详情按轮次呈现用户提问及 AI 正式回复；未完成轮次展示提问和未完成状态。
- 每次打开／切换会话，默认定位到聊天流底部；搜索框占位文案为“搜索会话”。
- 会话详情采用聊天流：用户消息在右侧灰色气泡中显示，时间位于气泡上方；AI 回复在左侧展开正文，头部展示工具标识、名称、时间和已有模型信息。缺失的模型或时间不编造。
- 聊天栏仅显示聊天流，删除顶部重复的会话标题、项目／来源／轮次数摘要；会话标题保留在中间列表中。
- 助手头像按会话来源 provider 使用对应 Agent 的图标，保留原始品牌标识；不可使用 weekly report 图标，也不能因模型切换而把宿主图标换成模型厂商图标。图标文件和来源记录见 [Agent 图标素材](assets/agent-icons/README.md)。
- AI 正式回复保留 Markdown 排版，包括段落、列表、强调和代码；多轮自然连续呈现，不再使用逐轮分隔的提问／回复表单样式。
- 参考图中的执行过程折叠项不改变原采集范围：仍只读取、上传和展示用户提问与 AI 正式回复。附件的采集与上传范围尚未确定，不能仅凭布局参考图扩大范围。
- 尚未上传的获准会话也可在首页查看，首页不是上传成功记录的副本。
- 会话列表上方有「搜索会话」，列表分「全部 / 未上传 / 不上传」三个视图；每行显示来源、更新时间、轮数和上传状态（已上传、未上传、不上传）。
- 成员可以让项目内的单个会话不上传：选中会话后点详情上方的「不上传此会话」，或在列表行上点右键；随时可以「恢复上传」。选择保存在本机，重启后仍然有效。
- 不上传的会话不会进入任何上传包；如果它已经在排队的待传包里，该包作废并重新打包，不会被发出去。已经上传过的内容不会撤回，仍保存在公司系统中，需要删除请联系团队管理员。
- 来源数量、项目数量、搜索结果和正文仅使用已批准项目；未批准项目不因首页预览而被读取正文。

### 隐私说明

左侧导航在「上传记录」之后有「隐私说明」页，用通俗的话讲清：哪些内容会上传（只有已允许的项目，只有提问和正式回复）、上传前在本机去掉密钥、令牌和口令（其余内容原样上传）、上传到哪里和谁能看到（团队管理员可查看原文，原文长期保留，整理工作卡时交给公司配置的 AI 模型）、成员可以决定什么，以及已上传的内容不会撤回。页面顶部显示实时设置：允许采集的项目数、不上传的会话数、自动上传是否开启，并提供到项目审批、项目会话和上传设置的入口。

### 上传记录与频率

- 显示上传批次、时间、涉及项目与工具、会话／轮次数量、成功或失败结果，以及补传情况。
- 直接呈现上传安排和上传记录，不重复显示“上传与频率”的页面大标题和说明文字。
- 保留上传频率、计划时间设置及自动上传的开启／暂停状态；删除额外的“下次自动上传”展示行。
- 网络恢复后默认补传仍获允许的项目，不提供可关闭的补传选项，也不将“只上传获准项目”作为可选开关。
- 提供手动上传入口；失败记录应说明原因与后续处理状态。
- 页面标题单独一行；时间范围放在工具栏，「立即上传」旁边显示这次会带上多少会话，以及有多少个会话被设为不上传。
- 上传频率只支持“每天一次”和“每周一次”，使用并排选择按钮，不使用频率下拉框；两种方式均可设置时间，每周一次还可选择星期。
- 上传安排和本地会话发现／刷新是不同概念，不能因为手动筛选会话就触发未授权采集。

### 配置与设置

- 直接展示账号与系统、应用偏好等配置分组，删除重复的页面大标题及说明文字。

- 成员绑定和连接状态。公司系统地址由 App 内部部署配置决定，不呈现给用户，也不提供编辑字段。
- 工具来源及会话目录配置、目录访问状态。
- 项目文件夹登记与审批结果；无 Git 项目也可登记，登记后仍需审批。
- 登录自启动、关闭窗口后的菜单栏运行、应用版本与更新。
- 应用偏好增加独立的“自动更新”开关，同时保留手动“检查更新”和更新状态。草图示例将开关开启，最终默认值仍属于设计建议。
- 自动更新开启时，建议自动检查和下载，经校验后等待当前采集、上传任务完成并持久保存进度，再安装和重启；关闭时仅由用户手动检查、下载和安装。不能把“自动检查更新”误称为已实现自动安装。
- 更新包及版本清单由公司部署的更新源提供，具体检查间隔尚未确定；更新安排独立于会话上传频率。源码依据和实现边界见 [CC Switch 更新链路分析](research/cc-switch/app-update.md)。
- 待审批／未允许项目仅在这里显示其项目定位与审批状态，不在首页提供会话预览。

## 原有方案的调整

原“菜单栏概览 + 我的项目 + 上传记录 + 设置”草图不再作为应用主结构。新的核心是可浏览会话的首页，上传管理和配置各占一个页面；菜单栏面板的具体精简内容可随后确定。
