# weekly report · 原生 macOS App

SwiftUI + AppKit 构建的桌面 App，最低 macOS 14。默认窗口为 1280 × 860，最小窗口为 960 × 720。侧边栏依次为待审批项、项目会话、上传记录、系统设置、个人数据、隐私说明（⌘1…⌘6，隐私说明始终在最后，新页面插在它之前），并保留菜单栏入口。

正式入口现已接入中台采集服务；原有工作卡片审核客户端仍保留但尚未接入。演示模式不会联网或扫描真实会话。

## 绑定与采集流程

1. 首次启动只填写名字和绑定码，系统地址由构建配置固定为本地 `http://127.0.0.1:4314`。名字必须与中台成员信息一致；Token 仅存 Keychain。上线时修改 `project.yml` 的 `WEEKLY_REPORT_SERVICE_URL` 并重新构建，生产地址要求 HTTPS。切换地址后需重新绑定。
2. 绑定后展示中台已有的已允许、已拒绝与待确认项目，新成员为空。可以直接修改权限；版本冲突时刷新而不自动覆盖。为已有项目显式选择对应本机文件夹，不凭同名项目自动继承授权。
3. 点击开始扫描，导入截至点击时最近一个自然月、且已获授权的项目会话。扫描定位元数据用于识别项目，拒绝或待确认项目不读取正文。首次导入完成后进入原有主界面。
4. 手动上传或按每天／每周定时上传时，重新扫描当前中台采集周期，将周期内允许项目的完整会话打包上传，不再上传贡献摘要或只传新增消息。只有提问的会话也保留。部分读取失败会阻止整批上传。
5. 会话包分块校验、可重复提交，只有服务器整批确认后才更新上传检查点；失败队列落盘并在重启后重试。权限变更会作废旧包，重新按当前授权打包。
6. App 上报启动、绑定、权限、项目发现、扫描、上传、通知、审核及每分钟在线日志，并附带白名单诊断细节（耗时、HTTP 状态、错误类别、计数）。日志不包含会话正文、本机路径、凭据或任意异常原文。网络恢复后补传。中台“用户日志”按成员展示设备状态、日志时间线和周期包接收状态。

接口、数据库迁移、部署与验收说明见 `docs/APP_COLLECTION_WORKFLOW.md`。完全退出 App 后不会执行扫描、上传或心跳。

## 本地测试模式

下列本地行为仅保留给未注入 `CollectorServing` 的核心测试与旧 smoke 脚本，不是正式 App 的工作流。正式入口不使用邮箱本地绑定或本地假上传。

首次使用先展示欢迎页，点击“开始扫描本机会话”后才执行扫描。目录扫描按真实阶段显示进度，随后逐条加载全部已允许项目的会话正文，按实际处理数量更新进度；待审批、已拒绝和已归档内容不读取正文。首次扫描和项目的“允许采集”都必须等内容加载、筛选和标题整理完成后才进入页面。读取失败会停在结果页，提供重试或返回，不把失败当成成功；重试复用已成功读取的缓存。中断采集后重启仍须完成加载。首次扫描完成状态保存在本机，后续正常启动直接进入 App。欢迎页期间不启动后台扫描、正文读取或通知授权。

成功解析后，整个会话没有任何非空正式模型回复的记录（包括空壳、只有用户提问、只有空白回复）不进入会话列表、会话数量和待传队列。已有正式回复、只是最后一轮尚未完成的会话仍保留。筛选结果按源文件指纹缓存，源文件新增回复后会重新读取、重新判断；读取失败或部分读取受限不作为“无回复”隐藏。

待审批项分为“项目审批”和“工作卡片”。项目在同一张表内按待审批、已允许、已拒绝分组，无状态切换分页；允许／禁止后实时移动分组。工作卡片使用左列表右详情，提供待审核／已处理与周期筛选，支持通过、忽略（含确认）、填写修改意见后重新生成，没有项目阶段选择器。演示重生成仅标记为“本地示例修改意见”，不会调用模型或远程服务；真实模式仍不连接审核服务。

默认启动使用真实模式，不预置虚构项目或聊天记录。首次点击开始按钮后扫描 Agent 与会话目录，将实际路径和扫描结果记在当前用户本机；后续启动复查已发现路径：

1. 首次点击开始按钮后从各 Agent 的本机会话定位信息发现项目，进入 App 后每分钟复查；切回 App、电脑唤醒后立即复查，也可手动刷新；识别 Git 根或手动登记目录，忽略临时会话。
2. 新项目进入“待审批项”，通过 macOS 原生通知提醒。选择“允许采集”后，才进入项目会话并调用 Rust 读取正文。“禁止采集”的项目保留在同页的已拒绝分组；项目菜单可停止采集。添加项目和更换项目文件夹都用原生文件夹选择器，更换目录后须重新授权。
3. 在首页选择项目、Agent 和会话，阅读真实提问、正式回复或未完成状态。项目获准后读取 Agent 保存的真实标题／重命名，没有标题时才回退到提问；未完成标题读取时暂时展示来源与时间。
4. “立即上传”在本地模式中准备待传队列，状态始终为“待上传”；没有配置远程接收端，不会发送网络请求，也不会假装上传成功。断网补传是正式产品的默认行为，本版没有可关闭的补传开关。
5. 项目确认、目录和偏好保存在当前用户 Application Support 的 `WeeklyReportLocal` 目录；实际待传文本放在其中的 outbox，目录权限 0700、文件权限 0600。

上传频率只提供每天／每周；每周的星期选择与时间放在同一行。旧版间隔频率迁移为每天一次。账户连接已改为名字和绑定码；核心测试的 `saveBinding` 不能创建正式联网凭据。

会话列表纵向滚动，项目与 AI 工具筛选并排。示例上传使用消息摘要检查点区分旧内容与新增内容；新增回复或修改回复会回到未上传状态，阅读区显示上次上传分割线。真实模式在收到远程确认前始终保持未上传。

上传记录按整个批次展示，详情弹窗按项目分组。系统设置仅包含账户连接、采集来源、自动上传。聊天记录位置支持下拉展开多个目录，没有重复数量标记。左下角仅在发现可安装的新版本后显示红色 New，点击直接开始更新；持续 24 小时未点击则自动更新。下载、签名验证及替换重启交给 Sparkle。

## 版本更新

`project.yml` 的 `WEEKLY_REPORT_UPDATE_FEED_URL` 指向 GitHub main 分支上的 `apps/macos/appcast.xml`，`WEEKLY_REPORT_UPDATE_PUBLIC_KEY` 是 Sparkle Ed25519 公钥。签名私钥仅保存在本机 Keychain 的 `com.weeklyreport.desktop.updates` 账户，不进入仓库。更新源与构建配置中的系统地址相互独立，不使用工作邮箱或会话数据。清空更新地址或公钥时更新器不会启动。

首次发现新版本的时间单独保存在 `WeeklyReportLocal/app-update.json`。重启后先重新检查可用版本，再恢复原来的 24 小时截止时间；期间发布更高版本不会延长已经显示的 New 的期限。到期后如 App 已退出或设备正在休眠，在下次启动／唤醒并确认版本可用后执行。更新失败保留原期限，后续检查发现同一更新时重试。正在下载或安装时显示进度指示，防止重复点击。演示及截图模式不会启动真实更新器。

发布前递增 `MARKETING_VERSION` 和 `CURRENT_PROJECT_VERSION`，运行 `apps/macos/scripts/prepare-update.sh`。脚本构建 Release App、校验签名、打包 ZIP，并用 Keychain 私钥生成和校验 appcast，输出保存在 `.local/weekly-report/releases/`。先把 ZIP 发布到脚本给出的 `macos-v版本号` GitHub Release，再将生成的 appcast 复制到 `apps/macos/appcast.xml`，提交并推送 main。这样更新源只会指向已经存在的下载包。发布时使用 `--latest=false`，保留团队既有稳定版 Release 的 Latest 标记。

2026-11-03 的更新测试使用 `0.2.1 (5)` 作为起始版本，发布 Apple Silicon 的 `0.2.2 (6)`。此前安装的 App 没有更新源或公钥，必须先手动安装一次带上述配置的起始版本，之后才可点击 New 测试下载、签名验证、替换安装和重启。脚本按构建主机架构打包，与 Rust Reader 保持一致。当前为本机 ad-hoc 签名开发分发，正式公开分发仍需 Developer ID 签名和公证。复用此发布链路前须保留或迁移对应 Keychain 私钥。

项目采集授权在本机 App 内完成；每个实际目录有自己的身份，同名目录不会自动继承权限。源码预置的 `--demo` 模式仅用于纯界面验收，不是默认入口。

## 个人数据

侧边栏「个人数据」是 Web 领导视图「成员详情页」的只读副本，只显示绑定成员自己的数据：成员名与四个指标（负责的项目、需要关注、近 28 天活跃、最近活跃）、「负责的项目」卡片（超过两行可展开）、会话活跃度折线图（按天／按月，多项目时每个项目一条线并加虚线「总计」；按月视图点击某天跳到该天）、以及「项目详细进展」（项目目标与产品介绍、路线图、当前重点、项目进展、研发日历）。不含参与时间核查和查看周卡。

- 接口：`GET /v1/collector/personal-data[?month=YYYY-MM]`，用绑定时保存的 Bearer 令牌；成员只由令牌决定。`month` 只翻动研发日历，活跃度固定为近 90 天，按团队时区的字符串分桶，不受本机时区影响。研发日历的上个月／本月／下个月会重新请求对应月份。
- 打开页面或点刷新按钮时加载，刷新保持当前翻到的月份；失败保留已显示内容并给出重试，401 与其他页面一样回到绑定。
- 解码对缺失的可选字段（`profile`、`current`、`blocker`、`idle` 等）和未知字段／未知枚举值宽容。模型与分桶、日历网格等纯逻辑在 `Sources/Core/PersonalData.swift`、`PersonalActivity.swift`，界面在 `Sources/App/Personal*.swift`；图表使用 Swift Charts。
- 演示模式（`--demo`）用 `DemoPersonalData.swift` 的示例数据，无需服务端。

## 审批与通知

- 当前页面仅处理本机项目权限。会话来源用图标堆叠展示，一个项目可对应多个工具。
- 首次有待办时请求系统通知授权；拒绝后仍可在 App 内审批。设置页可打开系统通知设置。通知只显示类型与数量，不把本地路径、项目名称或卡片正文放进锁屏通知。
- 按项目／卡片合并通知，成功提交给系统后持久化去重记录；扫描、切回 App 和重启不会重复通知同一待办。处理完对应类型的待办后清理旧通知。系统接受通知不代表用户已经看到，勿扰模式和系统设置仍可阻止横幅显示。
- 监测由 App 生命周期持有。关闭窗口后继续在菜单栏运行，切回 App 和唤醒时复查本地目录。完全退出 App 后不运行后台守护进程。
- 首次真实启动默认注册 macOS 登录项；系统仍可能要求用户在系统设置中允许。用户之后关闭登录项时，App 不会每次启动强制重新打开。演示和截图模式不注册登录项。

真实账号与服务器未在本机验收中使用；系统横幅及通知点击仍需用户授予通知权限后进行真机验收。

## 构建

需要 Xcode、XcodeGen、Rust 和 C 编译器：

```sh
apps/macos/scripts/build.sh
```

脚本把独立 Rust 核心编译进 App 的 Resources，然后生成 Xcode 工程、构建原生 App。这里的 `Reader/` 是有来源记录和 MIT 许可的独立核心副本，不依赖相邻 CC Switch 仓库。

输出：`.local/weekly-report/DerivedData/Build/Products/Debug/weekly report.app`。

使用本机 ad-hoc 签名封装 App，确保系统通知能识别稳定的 Bundle ID；没有开发者身份签名或公证，当前是本机开发构建。启动：

```sh
open '.local/weekly-report/DerivedData/Build/Products/Debug/weekly report.app'
```

旧本地测试支持显式授权参数；正式联网入口忽略其授权效果，始终以中台策略和用户在 App 中的决定为准：

```sh
open '.local/weekly-report/DerivedData/Build/Products/Debug/weekly report.app' --args --authorize-project /path/to/approved-project
```

测试：

```sh
xcodebuild -project apps/macos/WeeklyReport.xcodeproj -scheme WeeklyReport \
  -derivedDataPath .local/weekly-report/DerivedData -destination 'platform=macOS' \
  CODE_SIGNING_ALLOWED=NO test
```

生成的 Xcode 工程和编译产物不进 Git。图标资源从 `docs/assets/agent-icons` 和 App 的标识生成，不依赖网页或 WebView。`scripts/prepare-assets.swift` 用 AppKit 转换原始资源。

## 当前覆盖与限制

- Codex：只读 state SQLite 的定位列，不取未批准项目的 title、preview 或 first_user_message。补充按文件名识别的历史续接文件，过滤子代理。
- Claude、Pi、OMP：按合法深度读取开头的 cwd／会话身份，过滤子任务；不为候选项目提取消息正文。
- OpenCode、Hermes：只读 session 的目录与关系字段；读取组件会再次核验实际目录和父子关系。
- Antigravity 同时检查 CLI、桌面及 profile brain，按独立元数据库核验授权，已用真实桌面会话验证。
- Grok Build 已接通 summary 身份／项目校验、原生标题、chat_history 与 events 结束信号；本机抽查 3 个会话、12 轮提问和 12 条正式回复。
- 来源范围仅限用户选定的 8 种，已移除 DeepSeek Harness、OpenClaw、MiniMax Code、Gemini CLI 和 Kimi Code。8 种已知本机格式均有真实提问和正式回复证据；Hermes 读取原生 finish_reason，缺少结束证据的旧记录仍保留未完成状态。不能把保留图标或编译通过当成全部来源已支持。
- JSONL 读取定位字段可能经过含正文的缓冲区，SQLite 数据页也可能含邻接数据；这里只承诺未批准前不提取、缓存或展示正文，不宣称实现字节级物理隔离。
- 部分跨项目会话会被 Rust 核心整份拦截；真实标题、时间、模型缺失时不编造。
- 已归档目录和支持的数据库归档标记均从发现、标题读取和待传队列中排除；已准备内容在重新发现或撤销授权后清理。
- 更新源和签名公钥已配置；更新包通过 GitHub Release 分发，业务接口当前仍指向本机。登录启动注册需在实际安装位置验证。
- 正式入口在 App 运行期间按设置定时上传，失败每分钟检查补传；完全退出不运行后台守护进程。

纯示例模式：`open ... --args --demo --preview-reset`。用 `--capture /absolute/path --capture-exit` 可输出本 App 自身的四个页面、三个设置页签、每周时间、上传详情弹窗及 960 × 720 窄窗口截图，完成后退出。演示模式不扫描真实会话、不注册登录项、不请求通知权限；不捕获其他应用画面。

完整来源覆盖矩阵及未支持项见仓库文档 `docs/AGENT_SOURCE_COVERAGE.md`。默认目录与自定义目录是补充关系，不会因为配置一个额外来源就隐藏默认来源。

本机逐项复查：`scripts/audit-agents.swift` 复用同一发现与读取组件，只对传入状态中已允许的项目抽样（每种工具最新最多 3 个会话），只输出计数和错误，不改授权、不上传。使用构建产物中的 `WeeklyReportCore.framework` 编译运行；三个参数依次为打包 Reader、已有本地 state.json、私有结果目录。最新结果及限制见来源覆盖矩阵。

目录发现、来源上下文与 CC Switch 的逐段对照见 `docs/CC_SWITCH_EXTRACTION_AUDIT.md`。`Reader/LOCATE.md` 记录独立元数据定位命令，供无索引／压缩历史、旧文件存储与 App 发现阶段共用。首次扫描记录在 `source-discovery.json`，仅保存实际目录、扫描状态及路径相关环境变量白名单，不保存密钥或正文。
